# Agent Instructions

## Project Rules

- Read REQUIREMENTS.md before implementing.
- Read SPEC.md before implementing.
- Read ARCHITECTURE.md before making architectural changes.
- Follow TASKS.md.
- Prefer small, focused changes.
- Do not invent or add business requirements.
- Do not modify REQUIREMENTS.md or SPEC.md to make tests pass.
- Do not delete, weaken, or bypass tests.
- Do not add dependencies without justification.
- Keep implementation consistent with REQUIREMENTS.md, SPEC.md, and ARCHITECTURE.md.

## Validation

- Run pytest before making changes to establish the current test status.
- Run pytest after changes.
- Add tests for new behavior.
- Report changed files and test results.
- Stop and ask for clarification if requirements, specifications, or architectural decisions conflict.

## Definition of Done

- Relevant tests pass.
- Acceptance criteria are covered by tests.
- The implementation satisfies the applicable requirements and specification rules.
- No unrelated files are changed.
- Documentation reflects the final implemented behavior.
